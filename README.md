# Табель смен: автозаполнение по фото из Telegram

Сервис читает сообщения из рабочих Telegram-групп. Фото с подписью, отправленное при заступлении на смену, превращается в **1** в табеле. По каждой отметке хранится основание: ссылка на сообщение, подпись, время и комментарий системы. Спорные случаи уходят оператору на ручную проверку.

**Стек:** Next.js 15 (App Router) · TypeScript · Prisma 6 · PostgreSQL (Neon) · Vercel · Telegram Bot API (вебхук) · Google Sheets (Apps Script).

---

## Архитектура

```
 Telegram-группы (N шт.)                        Vercel (Next.js)
 ┌───────────────┐   webhook (POST, secret)    ┌──────────────────────────────────────────┐
 │ фото+подпись  │ ──────────────────────────▶ │ /api/telegram/webhook                    │
 └───────────────┘                             │  1. ingestUpdate()  — сохранить (PENDING) │
                                               │     идемпотентно: UNIQUE(chatId, msgId)   │
                                               │  2. 200 OK Telegram                       │
                                               │  3. after(): processMessage()             │
                                               │     ├ кто на фото    (lib/matcher.ts)     │
                                               │     ├ какая смена    (lib/shift.ts)       │
                                               │     └ решение → табель / проверка         │
                                               │                                          │
                                               │ /api/cron/retry  — добор PENDING/ERROR    │
                                               │ Админка: табель, проверка, журнал, ...    │
                                               └──────────────┬───────────────┬───────────┘
                                                              │               │ зеркало
                                                    Neon PostgreSQL     Google Sheets
                                                  (источник правды)    (Apps Script Web App)
```

**Почему так**

- **Сначала сохраняем, потом обрабатываем.** Вебхук синхронно пишет сообщение в БД и сразу отвечает. Если БД недоступна, Telegram получает 500 и повторяет доставку: он хранит апдейты до 24 часов, поэтому события не теряются. Обработка идёт после ответа (`after()`). Если она упала, сообщение остаётся `PENDING`/`ERROR`, и его добирает cron или кнопка «Дообработать».
- **Идемпотентность на уровне БД.** `UNIQUE(chatId, tgMessageId)` для сообщений и `UNIQUE(employeeId, shiftDate)` для отметок. Даже два параллельных фото одного сотрудника не создадут двух единиц: второе получит статус «Дубль» с записью в журнале.
- **Без AI.** Сотрудник определяется по правилам: подпись или привязанный аккаунт. Каждое решение объяснимо, и причина пишется в журнал.
- **Prisma без нативного движка** (`engineType = "client"` + `@prisma/adapter-pg`). Это лучше подходит для serverless и Neon: нет бинарников и холодный старт быстрее.

## Как система принимает решение

1. **Фильтр.** Обрабатываются только сообщения с фото (обычное фото или картинка документом) из групп и супергрупп. Текст не сохраняется.
2. **Группа.** Если группа не включена в учёт, сообщение получает статус `IGNORED`. Группы регистрируются автоматически, когда бота добавляют в чат.
3. **Альбом.** Основание — первое фото. Остальные фото альбома без подписи получают `IGNORED`.
4. **Кто на фото** (`lib/matcher.ts`):
   - подпись сравнивается со справочником: фамилия, позывные, табельный номер. Регистр, `ё/е` и пунктуация не важны; допускаются опечатка в 1 букву и падежные окончания («Македонского»). Однофамильцы уточняются по имени или инициалу;
   - поиск идёт только среди сотрудников, закреплённых за группой (если никто не закреплён — среди всех);
   - нет совпадения в подписи → по привязанному аккаунту Telegram отправителя;
   - не определён или неоднозначен → `REVIEW`.
5. **Какая смена** (`lib/shift.ts`). Берётся ближайшее начало смены по местному времени объекта. **Дата смены = дата её начала**, поэтому при смене с 23:00 фото в 00:20 относится к предыдущим суткам. Затем проверяется окно `[начало − до; начало + после]`; опоздание сохраняется в отметке.
6. **Решение:**

| Ситуация (п. 9 ТЗ) | Поведение |
|---|---|
| Фото без подписи | По привязанному аккаунту, иначе на проверку |
| По подписи не понять, кто | На проверку |
| Несколько сотрудников | Настройка группы: на проверку / отметить всех |
| Несколько фото подряд | Первое ставит 1, остальные — «Дубль» (с записью в журнале) |
| Слишком рано / поздно | Настройка группы: на проверку / отклонить |
| Сообщение отредактировано | Отметки не было → обработка заново. Отметка есть и сотрудник сменился → на проверку (1 автоматически не снимается) |
| Сообщение удалено | Bot API не присылает событий удаления (ограничение Telegram) — см. «Ограничения» |
| Много нерелевантных фото | Без подписи и аккаунта → на проверку; можно сузить список сотрудников группы |
| Повтор доставки вебхука | Пропускается (идемпотентность) |
| Бот временно недоступен | Telegram копит апдейты до 24 ч и повторяет; зависшие добираются cron |
| Группа не подключена | `IGNORED`, группа появляется в настройках выключенной |

Статусы журнала: `ACCEPTED` (принято), `REVIEW` (ручная проверка), `DUPLICATE`, `REJECTED`, `ERROR`, `IGNORED`, `PENDING`.

## Админка

| Раздел | Что там |
|---|---|
| **Табель** | Сетка «сотрудник × день» за месяц, как исходная таблица. Зелёный — авто, синий — вручную. Клик по ячейке показывает фото, подпись, ссылку на сообщение, решение системы и историю изменений, а также ручную постановку или снятие 1 с обязательной причиной. Выгрузка в .xlsx с листом «Основания» (приложение 1 ТЗ). |
| **На проверке** | Карточки спорных сообщений: фото, подпись, причина, предложенные сотрудники и дата → «Подтвердить» или «Отклонить». |
| **Журнал сообщений** | Все сообщения с фото, фильтр по статусу, группе и подписи, причина решения, «Повторить». |
| **История изменений** | Аудит всех изменений: кто, что и когда, по сотруднику и дате. |
| **Группы и объекты** | Включение группы, объект, начало смены, окно, часовой пояс, правила, закреплённые сотрудники. |
| **Сотрудники** | ФИО, позывные, табельный номер, Telegram ID. |
| **Интеграции** | Статус бота, установка вебхука одной кнопкой, проверка Google Sheets, дообработка очереди. |
| **Симулятор** | Отправка фейковых сообщений и прогон 16 сценариев из ТЗ с проверкой «ожидалось/получилось». |

Вход по паролю из `ADMIN_PASSWORD`. Роли пользователей в v1 не делались, это осознанное упрощение.

## Запуск локально

Нужны Node.js 20+ и база PostgreSQL. Проще всего сразу взять Neon, локальный Postgres тоже подойдёт.

```bash
npm install
cp .env.example .env          # заполнить DATABASE_URL, DIRECT_URL, ADMIN_PASSWORD, AUTH_SECRET
npx prisma migrate deploy     # создать таблицы
npm run db:seed               # демо: 8 сотрудников из табеля + 2 группы
npm run dev                   # http://localhost:3000
```

Дальше: **Симулятор → «Прогнать 16 сценариев»**, затем смотреть Табель, «На проверке» и Журнал.

Тесты: `npm test` (сопоставление подписи и расчёт даты смены, включая ночные смены и часовые пояса).

> На Windows вместо `cp` используйте `copy .env.example .env`.
> Prisma CLI читает именно `.env`, а не `.env.local`.

## Деплой (Vercel + Neon)

1. **Neon** (neon.tech): создать проект и взять две строки подключения:
   - `DATABASE_URL` — pooled (в хосте есть `-pooler`);
   - `DIRECT_URL` — direct (без `-pooler`), для миграций.
2. **GitHub**: запушить репозиторий.
3. **Vercel**: Add New → Project → импортировать репозиторий. В Environment Variables добавить всё из `.env.example`. Build Command оставить по умолчанию: `npm run build` сам выполнит `prisma migrate deploy`.
4. Открыть сайт, войти и выполнить `npm run db:seed` локально с продовой `DATABASE_URL`, либо нажать «Загрузить демо-справочник» в симуляторе.
5. **Telegram-бот:**
   - @BotFather → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`;
   - `/setprivacy` → выбрать бота → **Disable**. Иначе бот в группе видит только команды. Альтернатива — сделать бота админом группы;
   - в админке: **Интеграции → «Установить вебхук на этот домен»**;
   - добавить бота в рабочую группу. Она появится в «Группы и объекты»: включить, задать начало смены и окно, закрепить сотрудников.
6. **Google Sheets** (необязательно): инструкция в шапке `google-apps-script/Code.gs`. Если коротко: вставить скрипт в таблицу, задать свойство `SHEETS_SECRET`, развернуть как веб-приложение, URL положить в `SHEETS_WEBHOOK_URL`.

**Тестовая группа за 2 минуты:** создать группу в Telegram, добавить бота (privacy выключен), включить группу в админке, привязать свой Telegram ID к сотруднику (узнать ID можно у @userinfobot) и отправить фото с фамилией в подписи.

Для локальной проверки живого вебхука нужен https: подойдёт `ngrok http 3000`, затем «Установить вебхук» из админки, открытой по ngrok-адресу.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` / `DIRECT_URL` | Neon: pooled для приложения, direct для миграций |
| `ADMIN_PASSWORD`, `AUTH_SECRET` | Вход в админку, подпись cookie |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TELEGRAM_WEBHOOK_SECRET` | Telegram присылает его в `X-Telegram-Bot-Api-Secret-Token`, чужие запросы отбрасываются |
| `SHEETS_WEBHOOK_URL`, `SHEETS_SECRET` | Apps Script Web App (необязательно) |
| `CRON_SECRET` | Защита `/api/cron/retry` (Vercel передаёт его сам) |

## Нагрузка и масштабирование

Расчёт: 200 групп × несколько тысяч фото в сутки ≈ до 1 млн сообщений в сутки, в среднем 10–20 в секунду, пики выше.

- Вебхук только пишет одну строку и отвечает; serverless-функции масштабируются горизонтально. `max_connections: 40` в `setWebhook` позволяет Telegram доставлять параллельно.
- Обработка лёгкая: несколько индексированных запросов, без ML.
- Если `after()` упёрся в лимиты, сообщения остаются `PENDING` и добираются ретраем; потерь нет.
- **Следующий шаг при росте:** вынести обработку в очередь (Upstash QStash / SQS) с отдельными воркерами, партиционировать `Message` по месяцам, архивировать старый журнал. Код к этому готов: `ingestUpdate` и `processMessage` уже разделены.
- На тарифе Vercel Hobby cron запускается раз в сутки, на Pro его можно запускать каждую минуту. Пока этого нет, есть кнопка «Дообработать сейчас».

## Ограничения и допущения v1

- **Удаление сообщений.** Bot API не сообщает об удалении. Отметка остаётся, оператор снимает её вручную, причина пишется в аудит. Полное решение — MTProto-клиент (userbot), но это отдельный компонент.
- **Ссылки на сообщения** работают для супергрупп (`t.me/c/...`, у участников группы) и публичных групп. У старых обычных групп ссылок нет, тогда хранится ID сообщения.
- **Фото не копируются:** хранится `file_id`, превью подтягивается из Telegram через прокси `/api/photo/[id]`, токен бота наружу не уходит. Если нужен архив на годы, добавить выгрузку в S3/R2.
- Одна смена на группу в сутки; разные графики задаются разными группами/объектами.
- Отметка — только факт выхода (1). Опоздание сохраняется в отметке, но отдельным статусом в табель не выводится.

### Ответы на открытые вопросы ТЗ (п. 16), принятые как допущения

| Вопрос | Допущение в v1 |
|---|---|
| Где таблица смен | Цифровой аналог в БД (источник правды) + зеркало в Google Sheets + выгрузка .xlsx |
| Как определяется сотрудник | Фамилия, позывной или таб. № в подписи; иначе привязанный Telegram-аккаунт |
| Единый шаблон подписи | Нет: свободный текст, ищем фамилию среди сотрудников группы |
| Опоздания, замены и т. п. | Хранится опоздание в минутах; замена — ручная отметка с комментарием |
| Привязка к объекту | Группа = объект/пост, объект пишется в отметку |
| Полностью автоматическая 1 | Настраивается флагом группы «Автоматически ставить 1» |
| Хранить фото | Нет, хватает `file_id` и ссылки (см. выше) |

```
prisma/
  schema.prisma          модель данных
  migrations/            SQL-миграции
  seed.ts                демо-справочник
src/lib/
  pipeline.ts            ingest → decide → apply; ручная проверка; ретраи
  matcher.ts             сопоставление подписи со справочником (+ тесты)
  shift.ts               определение даты смены и окна (+ тесты)
  marks.ts               постановка/снятие 1 + аудит
  sheets.ts              синхронизация с Google Sheets
  telegram.ts            Bot API: типы, ссылки, setWebhook, getFile

  api/telegram/webhook   вход Telegram
  api/cron/retry         добор очереди
  api/photo/[id]         превью фото
  api/export             xlsx
  (admin)/...            страницы админки
google-apps-script/Code.gs   приёмник для Google Sheets
```
